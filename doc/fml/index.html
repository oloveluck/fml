fml: the FHIR Mapping Language🔗ℹ

The FHIR Mapping Language, checked and run. You write a map from one structure to another in a .map (or .fml) file; raco fml checks it against the two StructureDefinitions, runs it over a resource, and emits the StructureMap. A map file is a Racket module whose transform is a function from source JSON to target JSON.

Held to the published corpora: the fhir-test-cases structure-mapping suite (6 of 6 executable tests), the matchbox engine’s maps and the FHIR mapping tutorial (43 of 43 parse, 37 of 37 tutorial results), and the FHIR R3/R4 inter-version maps (332 of 332 parse). Part of the fhir family.

1 Quick start🔗ℹ

1. Install. The packages are not on the Racket package server yet; clone the repositories side by side and install from source:

raco pkg install --link --auto fhir/fhir fhirpath vcl fhir/fhir-tx fml

2. Write a map. From a QuestionnaireResponse to an Observation:

#lang fml

map "http://example.org/StructureMap/bp-intake" = "BpIntake"

uses "http://hl7.org/fhir/StructureDefinition/QuestionnaireResponse" alias QuestionnaireResponse as source

uses "http://hl7.org/fhir/StructureDefinition/Observation" alias Observation as target

 

group BpIntake(source src : QuestionnaireResponse, target tgt : Observation) {

  src -> tgt.status = 'final' "status";

  src -> tgt.code = cc('http://loinc.org', '85354-9', 'Blood pressure panel') "code";

  src.subject as s -> tgt.subject = s "subject";

  src.item as item where linkId = 'systolic' -> tgt.component as c,

      c.code = cc('http://loinc.org', '8480-6', 'Systolic blood pressure') then reading(item, c) "systolic";

}

 

group reading(source item, target c) {

  item.answer as ans then {

    ans.value as v -> c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "value";

  } "answer";

}

3. Check it, then run it.

$ raco fml check intake.fml

$ raco fml intake.fml --transform response.json

{"resourceType": "Observation", "status": "final",

 "code": {"coding": [{"system": "http://loinc.org", "code": "85354-9", "display": "Blood pressure panel"}]},

 "subject": {"reference": "Patient/p1"},

 "component": [{"code": {"coding": [{"system": "http://loinc.org", "code": "8480-6", ...}]},

                "valueQuantity": {"value": 120, "unit": "mm[Hg]", "system": "http://unitsofmeasure.org", "code": "mm[Hg]"}}]}

check reports what the two structures decide, on the rule’s line: an element neither type has (intake.fml:9:3: fml check error: ‘subjct‘ is not an element of QuestionnaireResponse), a value whose type cannot go into the element, a wrong group call, a required target element no rule assigns (a warning). A rule that fails at run time (a check that does not hold, a cast that does not convert) is reported the same way.

2 Writing a map🔗ℹ

A map names its source and target types (uses), then groups of rules. A rule reads source elements (src.item as item where …), binds them (as), and writes targets (-> tgt.x = …); then calls another group or opens nested rules; the string at the end names the rule. Target values: a variable, a literal, a FHIRPath expression in parentheses, or a transform: create(’Type’), copy, reference, cast, evaluate, truncate, translate, uuid, and the constructors c (Coding), cc (CodeableConcept), qty (Quantity), id, cp, append. A choice element on either side (ans.value, tgt.effective) reads whichever variant is present and writes the variant of the value’s type; a repeating target appends; share v reuses one target element across rules. The language reference is the FHIR specification.

Logical models. A uses url the FHIR towers do not define (a form of your own design) is resolved as a StructureDefinition from current-data-source and the packages and registered as a type. Give the definitions with --structures <file|dir> on the command line or #:structures from Racket. In a project of FSH structures, raco fsh check does this for every .map file; the worked project is fhir-examples/examples/intake-maps, walked through in A mapping problem, solved.

3 Using it🔗ℹ

3.1 Command line🔗ℹ

raco fml map.fml

  

the StructureMap JSON

raco fml map.fml –transform src.json [–structures sds/]

  

run the map; print the target

raco fml check map.fml [–structures sds/] [–examples ex/] [–profile sd.json]

  

the map against its structures; examples transformed and the results validated

raco fml –parse-corpus dir/

  

parse every .map under a directory

raco fml –tck

  

the vendored corpora, with floors

A StructureMap .json is read wherever a .map is. --format text|json|outcome chooses how an error is reported. Exit codes: 0, 1 on an FML error or a suite regression, 2 on usage.

3.2 As a module🔗ℹ

(require "intake.fml") gives fml (the AST), structuremap (the StructureMap jsexpr) and transform, the map as a procedure: FHIR JSON (or a typed node) in, FHIR JSON out, with #:structures for logical models. A parse error is a compile error. Requiring the module registers the StructureMap, so structure-map and $transform find it by canonical. racket intake.fml prints the StructureMap.

(require (only-in "intake.fml" [transform intake->reading])
         fhir/operation (only-in fhir/conformance/operations ensure-valid))
; map, then validate against a profile
(~> response intake->reading (ensure-valid #:profile profile-url))

3.3 As a value or an operation🔗ℹ

(structure-map ref) turns a canonical, a parsed map or a StructureMap resource into a typed procedure, found among the maps registered in the process, then current-data-source, then the packages. StructureMap/$transform is the same as an operation, with the map as text (srcMap), a canonical (source) or a resource (sourceMap).

(require fml/registry fml/operations fhir/operation)
(define to-bp (structure-map "http://example.org/StructureMap/bp-intake"))
(smap-source to-bp)                                    ; 'QuestionnaireResponse
(to-bp response)                                       ; FHIR JSON in, FHIR JSON out
((compose-maps a b) x)                                 ; b after a
(apply-operation "StructureMap/$transform" response #:srcMap fml-text)

3.4 From Racket🔗ℹ

(require fml/parser/parse fml/structuremap fml/transform fml/check fhir/result/result
         fhir/r5/schemas fhir/serialize/from-json)             ; the engine needs a tower
(define m (ok-value (parse-fml text #:source "intake.fml")))
(fml->structuremap m)                                           ; the StructureMap jsexpr
(check-map m)                                                   ; (listof diagnostic)
(run-map m (ok-value (from-json response #:lenient? #t)))      ; typed source -> target jsexpr
(structuremap->fml sm)                                          ; a StructureMap back to the AST

4 A mapping problem, solved🔗ℹ

The problem: a clinic’s front desk records blood-pressure readings on an intake form of its own design, and the clinic’s record keeps them as Observations that must conform to its screening profile. One project (fhir-examples/examples/intake-maps) holds the two structures in FSH, the map between them, and an example form.

1. The structures. The form is a logical model; the record is a profile of Observation.

Logical: IntakeForm

Id: IntakeForm

* patientId 1..1 string "The patient's record id"

* measured 1..1 dateTime "When the reading was taken"

* systolic 1..1 integer "Systolic pressure, mm[Hg]"

* diastolic 1..1 integer "Diastolic pressure, mm[Hg]"

 

Profile: ScreeningBP

Parent: Observation

* status = #final

* code = http://loinc.org#85354-9

* subject 1..1

* effective[x] 1..1

* effective[x] only dateTime

* component 2..*

 

Instance: intake-1

InstanceOf: IntakeForm

* patientId = "p1"

* measured = "2024-03-01T09:00:00Z"

* systolic = 120

* diastolic = 80

2. The map. Its uses name the two structures by canonical; each rule reads one form element and writes the Observation element it feeds.

/// url = 'http://example.org/intake/StructureMap/IntakeToBP'

/// name = 'IntakeToBP'

uses "http://example.org/intake/StructureDefinition/IntakeForm" alias Intake as source

uses "http://example.org/intake/StructureDefinition/ScreeningBP" alias BP as target

 

group IntakeToBP(source src : Intake, target tgt : BP) {

  src -> tgt.status = 'final', tgt.code = cc('http://loinc.org', '85354-9', 'Blood pressure panel') "panel";

  src.patientId as id -> tgt.subject as s, s.reference = append('Patient/', id) "subject";

  src.measured as m -> tgt.effective = m "when";

  src.systolic as v -> tgt.component as c, c.code = cc('http://loinc.org', '8480-6', 'Systolic blood pressure'),

                       c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "systolic";

  src.diastolic as v -> tgt.component as c, c.code = cc('http://loinc.org', '8462-4', 'Diastolic blood pressure'),

                        c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "diastolic";

}

3. Check, run, use. raco fsh check examples/intake-maps compiles the structures, checks the map against them and transforms the example form, validating the result against the profile; misspell an element or forget the rule for code and the check says so on the line. raco fsh examples/intake-maps –pack intake.tgz packs both structures and the StructureMap into one package, from which the map is a typed procedure by canonical:

(require fml/registry fhir/sd/sd-index)
(parameterize ([current-sd-packages (list "intake.tgz" core)])
  (define to-bp (structure-map "http://example.org/intake/StructureMap/IntakeToBP"))
  (to-bp form))                                ; the Observation

Over HTTP, a server generated from that package serves the same map as StructureMap/$transform. The test that does all of this is fhir-examples/tests/intake-maps-test.rkt.

5 What the engine does🔗ℹ

A rule runs for every combination of its sources’ matches (where filtered, in its list mode first, last, not_first, not_last, only_one; check must hold or the rule fails naming itself; log goes to current-fml-log), then its targets in order, the dependent group calls and the nested rules. A target without a transform creates its element; with one source and one target the value is carried over: a primitive is copied and coerced to the element’s type ("12345" into an integer element is 12345), a complex value runs the types/type+ group whose parameter types match, or is copied whole. extends runs the parent group first. translate uses an embedded conceptmap block or a ConceptMap the terminology service can see. Errors name the rule and, for an unknown transform or group, what is supported.

6 In an editor, for an agent🔗ℹ

fml/support is what the family’s language server (fhir-lsp) and MCP server (fhir-mcp) load for FML: a map’s diagnostics (parse, then the check against its structures), the maps beside it as its project, the declarations as an outline, hover, go to definition (an imports url leads to the map that declares it), and completion of declared names and keywords. It is a fhir/lang/support value; $transform is already an operation, so no tool is added.

7 Limits🔗ℹ

  • Transforms. escape, dateOp and pointer raise unsupported transform. Target list modes other than share are accepted and ignored.

  • Declarations. imports resolve by canonical (registered maps, the data source, the packages); one that resolves nowhere is skipped. let constants, source types, cardinalities and default are parsed and dropped. In embedded FHIRPath the as operator is read as the target alias; use .as().

  • Against the reference. Every tutorial result the reference engine’s own tests assert is reproduced; two result files in the corpus are not among them (one for a map the reference never runs, one where it expects the run to fail, as this engine does), named in tests/matchbox-harness.rkt.

  • Versions and formats. The executor targets R5 (sources from other versions are read leniently). The suite’s four CDA tests (XML output) are skipped.

The AST (fml/parser/ast) is prefab: fml-map (url, name, metadata, uses, imports, groups, conceptmaps), fml-group, fml-rule (sources, targets, dependents, nested rules), fml-source, fml-target (context #f for a bare invocation), fml-conceptmap (name, prefixes, mappings); a transform is fml-literal, fml-fhirpath (a FHIRPath AST), fml-invoke or fml-var.

procedure

(fml->structuremap m) → hash?

  m : fml-map?
The StructureMap resource, the canonical compiled form of a mapping: status "active", unnamed rules named rule-N, conceptmap blocks as contained ConceptMaps.

procedure

(structuremap->fml sm) → fml-map?

  sm : hash?

The round trip returns the parsed AST up to the FML-only surface (/// metadata, conceptmap prefixes) and the rule-N names; every corpus map is checked.

fml/transform🔗ℹ

 (require fml/transform) package: fml

procedure

(run-map m source) → hash?

  m : fml-map?
  source : fhir?
Runs the map’s first group over a typed source node and returns the target resource as a jsexpr. Targets are shaped by the registered type schema (a repeating element appends, a value[x] takes the key of the value’s type, a primitive element coerces what is assigned to it). A failure while running a rule (a check that does not hold, only_one over several elements, a cast that cannot convert, an unknown group) raises exn:fail:diagnostic positioned at the rule, as a parse error is.

procedure

(uses-types m) → hash?

  m : fml-map?
The map’s uses resolved to type symbols, keyed by alias and type name; a structure the towers lack is resolved as a StructureDefinition (the current data source, then the packages) and registered. Call it before reading a source instance of a logical model.

fml/operations🔗ℹ

 (require fml/operations) package: fml

value

$transform : procedure?

StructureMap/$transform as a fhir/operation value, registered when the module loads: the subject is the content, #:srcMap the FML text. The content is read leniently into the R5 tower; sourceMap is a StructureMap resource and source a canonical (registered maps, the data source, the registry, the packages). A rule that fails at run time comes back as an OperationOutcome whose issue carries the rule’s file and line (the standard operationoutcome-issue-line extensions).
