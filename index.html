9.3

fml: the FHIR Mapping Language🔗

Health data rarely arrives in the shape you need it in. A patient fills in a questionnaire, and the record wants a Patient. A clinic’s front desk has an intake form of its own, and the clinic keeps blood-pressure readings as Observations. A system speaks one version of FHIR and its neighbour another. Each time, someone has to say which piece of the one becomes which piece of the other.

The FHIR Mapping Language (FML) is the standard way to write that down. A map is a text file of rules, and each rule reads "take this from the source, write that to the target". It is part of FHIR, the health-data standard, so a map written here can be read and run by other FHIR tools.

This package checks a map against the two shapes it converts between, runs it over your data, and points at the line when something is wrong.

Part of the fhir family of FHIR languages and tools.

1 What you can do with it🔗

  • Convert one piece of data: a filled-in form into a Patient (A first example).

  • Check a map before you run it: a misspelt element, a value of the wrong kind or a missing required element is reported at its rule (Checking a map).

  • Test a map on examples: convert each one, and be told which rule produced an invalid result (Checking a map).

  • Convert data that is not FHIR: a shape of your own, described once (Shapes of your own: logical models).

  • Use a map from a program: as a function from source data to target data (As a module, from Racket).

  • Exchange maps with other tools: as StructureMap resources, and read a StructureMap back as text (The StructureMap, and back to text).

2 A first example🔗

1. Install the tools as the family’s front page describes. The command is then raco fml (or fml, if you built the standalone tools).

2. Have something to convert. Here it is the answers to a two-question form, as FHIR records them: a QuestionnaireResponse, with one item per question. Each item names its question (linkId) and holds the answer. Save it as qr.json:

{"resourceType": "QuestionnaireResponse", "status": "completed",

"item": [{"linkId": "gender", "answer": [{"valueCoding": {"code": "female"}}]},

         {"linkId": "birth",  "answer": [{"valueDate": "1980-02-03"}]}]}

This is the source. What you want from it is a Patient with a gender and a birth date: the target.

3. Write the map, qr2pat.map:

/// url = 'http://example.org/StructureMap/qr2patient'

/// name = 'QR2Patient'

 

uses "http://hl7.org/fhir/StructureDefinition/QuestionnaireResponse" as source

uses "http://hl7.org/fhir/StructureDefinition/Patient" as target

 

group main(source src : QuestionnaireResponse, target tgt : Patient) {

  src.item as item where (linkId = 'gender') -> tgt.gender = (item.answer.value.code) "gender";

  src.item as item where (linkId = 'birth') then {

    item.answer as a -> tgt.birthDate = (a.value) "birthDate";

  } "birth";

}

Reading it from the top:

  • The two /// lines are the map’s header. url is the address the map is known by, so that other maps and tools can refer to it; it does not have to exist on the web. name is a short name for it.

  • Each uses line names one of the two shapes by the address of its definition, and says which side it is on. Every FHIR type has such an address under http://hl7.org/fhir/StructureDefinition/.

  • A group is a set of rules. This one takes a QuestionnaireResponse, which the rules call src, and fills in a Patient, which they call tgt. The names are yours to choose.

  • The first rule reads: for each item of the source whose linkId is 'gender', write the code of its answer to the target’s gender. The left of the arrow is what to take, the right is where to put it. The text in parentheses is FHIRPath, FHIR’s small language for picking values out of data.

  • The second rule finds the 'birth' item, and then opens a rule inside it: for each answer, write its value to birthDate.

  • The quoted word at the end of a rule is its name. Messages use it to say which rule they are about.

4. Check it. The check compares the map with the two shapes, without any data:

$ raco fml check qr2pat.map

qr2pat.map: 0 findings

No findings means every element the map names exists, and every value fits where it is put.

5. Run it over the form:

$ raco fml qr2pat.map --transform qr.json

{"resourceType":"Patient","gender":"female","birthDate":"1980-02-03"}

That is the target: a Patient with the two values the rules wrote. Add --indent to have it laid out over several lines.

6. Make a mistake. Write tgt.gendr in the first rule and check again:

$ raco fml check bad.map

bad.map:8:49: fml check error: `gendr` is not an element of Patient (did you mean `gender`?)

 8 |   src.item as item where (linkId = 'gender') -> tgt.gendr = (item.answer.value.code) "gender";

   |                                                 ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

bad.map: 1 finding

The message gives the file, the line and the column, and the name it thinks you meant. Running a map does not check it first: run this one and you get a Patient with a gendr element, which no FHIR tool will accept. So check, then run.

7. See what it compiles to. Run with no option and the map is printed as a StructureMap, the FHIR resource that holds a map as data:

$ raco fml qr2pat.map

{"group":[{"input":[{"mode":"source","name":"src","type":"QuestionnaireResponse"}, … ],

 "name":"QR2Patient","resourceType":"StructureMap","status":"draft", … }

You rarely need to look at it. It is the form in which maps are stored on FHIR servers and passed between tools; the text is the form you read and edit (The StructureMap, and back to text).

3 Writing a map🔗

This section goes through the parts of a map in the order you write them. The language itself is defined by the FHIR specification, and HL7’s mapping tutorial builds it up step by step.

3.1 The header, the shapes, the groups🔗

A map starts by saying what it is and what it converts:

/// url = 'http://example.org/StructureMap/bp-intake'

/// name = 'BpIntake'

/// title = 'Blood pressure from the intake questionnaire'

 

uses "http://hl7.org/fhir/StructureDefinition/QuestionnaireResponse" alias QuestionnaireResponse as source

uses "http://hl7.org/fhir/StructureDefinition/Observation" alias Observation as target

  • The header is one /// element = value line for each fact about the map. url and name are required. Others may follow, such as title or status; a map that states no status is a draft.

  • uses names a shape and its side, source or target. alias gives it a short name for the rest of the file; without one, the last part of the address is the name.

  • imports "<url>" lets a map call the groups of another map, named by its url.

  • A group is a named list of rules with its inputs in parentheses: group main(source src : QuestionnaireResponse, target tgt : Observation) { … }. The first group is where a run starts.

3.2 Rules🔗

A rule has a left side that reads the source and, after ->, a right side that writes the target. It ends with a semicolon, and may carry a name in double quotes before it. Here is a map with most of what a rule can do, a blood-pressure reading from a form:

group BpIntake(source src : QuestionnaireResponse, target tgt : Observation) {

  src -> tgt.status = 'final' "status";

  src -> tgt.code = cc('http://loinc.org', '85354-9', 'Blood pressure panel') "code";

  src.subject as s -> tgt.subject = s "subject";

  src.item as item where (linkId = 'systolic') -> tgt.component as c,

      c.code = cc('http://loinc.org', '8480-6', 'Systolic blood pressure') then reading(item, c) "systolic";

}

 

group reading(source item, target c) {

  item.answer as ans then {

    ans.value as v -> c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "value";

  } "answer";

}

  • Reading. src.subject as s takes the source’s subject and calls it s. When the element repeats, as item does, the rule runs once for each one. A bare src reads nothing in particular: the rule simply runs once.

  • Filtering. where (linkId = 'systolic') keeps only the items for which the condition holds. The condition is FHIRPath, in parentheses, and is asked of the element just read.

  • Writing. tgt.status = 'final' writes a fixed value; tgt.subject = s writes what the left side read; tgt.gender = (item.answer.value.code) writes what a FHIRPath expression in parentheses finds. Several writes are separated by commas.

  • Making a new part. tgt.component as c adds a component to the Observation and calls it c, so the writes after it can fill it in. An element that can repeat gets a new entry each time; one that cannot is set.

  • Built-in helpers, called transforms, make the values FHIR uses most. cc makes a coded concept from a code system, a code and a display text; qty makes a quantity from a number and a unit. The full list is in The built-in helpers (transforms).

  • Going deeper. then { … } opens rules inside a rule, which can use everything the outer rule named. then reading(item, c) hands the work to another group.

  • Elements that come in several kinds. FHIR writes an answer’s value as valueInteger, valueString, valueCoding and so on, depending on its kind, and an Observation’s value likewise. In a map you write just value: reading takes whichever is there, and writing picks the name from the kind of value, so the quantity above lands in valueQuantity.

Over a response whose subject is Patient/p1 and whose systolic item is answered 120, the map gives this (the middle is left out here):

$ raco fml intake.map --transform response.json --indent

{

  "resourceType": "Observation",

  "status": "final",

  "code": {

    "coding": [

      {

        "system": "http://loinc.org",

        "code": "85354-9",

        "display": "Blood pressure panel"

      }

    ]

  },

  "subject": {

    "reference": "Patient/p1"

  },

  "component": [

    {

      …

      "valueQuantity": {

        "value": 120,

        "unit": "mm[Hg]",

        "system": "http://unitsofmeasure.org",

        "code": "mm[Hg]"

      }

    }

  ]

}

3.3 More that a rule can say🔗

These are the remaining forms of the language. Each of them runs here.

/// url = 'http://example.org/StructureMap/forms'

/// name = 'Forms'

 

uses "http://hl7.org/fhir/StructureDefinition/QuestionnaireResponse" as source

uses "http://hl7.org/fhir/StructureDefinition/Observation" as target

 

let loinc = 'http://loinc.org';

 

group main(source src : QuestionnaireResponse, target tgt : Observation) {

  src.status : code 1..1 as s -> tgt.status = 'final' "status";

  src.language default ('en') as l -> tgt.language = l "language";

  src.item first as item where (linkId = 'weight') check (item.answer.exists()) log (item.linkId) ->

    tgt.code = cc(loinc, '29463-7'), tgt.value = qty(item.answer.value, 'kg') "weight";

  src -> tgt: id, implicitRules;

}

  • let loinc = 'http://loinc.org'; is a constant: a name for a value that every group can use.

  • src.status : code 1..1 says what kind of value the source element is and how many there must be. Fewer or more is an error at the rule.

  • default ('en') is the value to use when the source has none.

  • first takes only the first of a repeating element. last, not_first, not_last and only_one are the others; only_one is an error when there are several.

  • check (…) must hold, or the run stops with an error naming the rule. log (…) hands a value to the program that runs the map as the rule runs, for finding out what a map did (current-fml-log); the command line does not show it.

  • src -> tgt: id, implicitRules; is short for copying each named element across as it is.

  • tgt.name as n share lets several rules fill in the same new part, where each would otherwise add its own.

  • An element whose name is also a word of the language is written in backticks: src.`group`.

3.4 Two things that catch newcomers🔗

  • A code is not a coding. A form answers a coded question with a small object, a system and a code. A Patient’s gender holds only the code. Assign the object and the run stops, with the part to use:

    coding.map:9:5: fml transform error: Rule "gender": `tgt.gender` is a code, but the rule assigns an object {code}: assign its `code`, `(a.value.code)`

  • as inside FHIRPath. In a rule, as always names something, so FHIRPath’s own as operator cannot be written inside the parentheses. Use the function form, (v.as(Quantity)).

3.5 Maps written the older way🔗

Many published maps were written for an earlier version of the language. They leave the parentheses off a condition (where linkId = 'x'), put where before the name, start with map "url" = "name" in place of the header lines, or hold a table of code translations in a conceptmap block. All of these are read and run. The check points out the ones the specification no longer has, as warnings:

$ raco fml check old.map

old.map:8:20: fml check warning: `where linkId = 'gender'`: the specification writes the expression in parentheses — `where (linkId = 'gender')`

 8 |   src.item as item where linkId = 'gender' -> tgt.gender = (item.answer.value.code) "gender";

   |                    ^^^^^^^^^^^^^^^^^^^^^^^

old.map: 1 finding

4 Checking a map🔗

A map can be wrong in two ways: it can disagree with the shapes it converts between, or it can produce a result that is not valid. raco fml check looks for both.

4.1 Against the two shapes🔗

With no data at all, the check reads the definitions of the source and target types and reports, at the rule:

  • an element the type does not have, with the nearest name: `subjct` is not an element of QuestionnaireResponse (did you mean `subject`?);

  • a value of a kind the element cannot hold;

  • a call to a group that does not exist, or with the wrong number of inputs;

  • a required target element that no rule writes. This one is a warning, since another map may fill it in:

    $ raco fml check nocode.map

    nocode.map:7:1: fml check warning: Observation.code is required (min 1) but no rule of BpIntake assigns it

     7 | group BpIntake(source src : QuestionnaireResponse, target tgt : Observation) {

       | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

    nocode.map: 1 finding

  • a way of writing the specification no longer has (Maps written the older way), also a warning.

The command ends with status 1 when there is an error and 0 when there are only warnings. What the check cannot decide, it does not report: a type whose definition it cannot find is left alone.

4.2 On examples🔗

Give the check some source data with --examples (a file or a folder) and it converts each one and validates the result: it asks whether the result is correct FHIR of its type. A problem is traced back to the rule that wrote the element.

Often the result must meet stricter rules than FHIR’s own. Those are written as a profile: a statement of what a resource must contain in your setting. This one, in FHIR Shorthand, says an intake Patient must have a gender and a birth date (fsh/intake.fsh):

Profile: IntakePatient

Parent: Patient

Id: intake-patient

* gender 1..1

* birthDate 1..1

Name the profile with --profile and the results are held to it. Here forms/ holds the first example’s form as ann.json, and a second, bo.json, where the gender was typed as text rather than chosen from a list:

$ raco fml check qr2pat.map --examples forms/ --profile fsh/

qr2pat.map:8:49: fml validate error: forms/bo.json: Patient.gender: minimum required = 1, but found 0 (the rule here wrote nothing: its source matched, but `(item.answer.value.code)` was empty for {"answer":[{"valueString":"male"}],"linkId":"gender"})

 8 |   src.item as item where (linkId = 'gender') -> tgt.gender = (item.answer.value.code) "gender";

   |                                                 ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

qr2pat.map: 1 finding, 2 examples validated (forms/ann.json, forms/bo.json) against IntakePatient (http://example.org/StructureDefinition/intake-patient)

The message says which example failed, what is missing, which rule should have written it, and why it did not: the rule asked for the answer’s code, and a text answer has none. The last line says what the results were held to.

--profile takes a profile as a JSON file, a folder or file of FHIR Shorthand, or the address of a profile in an installed package. Repeat it for several.

4.3 When a result is missing something🔗

The messages try to say why an element was not written:

  • (no rule of main writes `birthDate`): the map has no rule for it. Add one.

  • (the rule here wrote nothing: its source matched nothing in the input): the rule is there, but the data had nothing for it to read.

  • its source matched 2 items, but `where (linkId = 'gender')` held for none (the linkId there: gendr, birth — did you mean 'gendr'?): the data was there and the condition turned it away. The message lists the values the condition was tested against, and the nearest to the one you wrote. Here the form spelt the question gendr.

  • was empty for …, as above: the rule ran, and the value it asked for was not there.

One more thing can hide data from a map. A value that is not valid FHIR, such as a date written 01/05/1950, cannot be read at all, so no rule sees it. The run says so:

$ raco fml qr2pat.map --transform cy.json

cy.json: warning: item[1].answer[0].valueDate ("01/05/1950") not read: not a valid value, or not an element of QuestionnaireResponse in FHIR R5

{"resourceType":"Patient","gender":"male"}

5 Shapes of your own: logical models🔗

The source of a map does not have to be FHIR. A logical model describes a shape of your own, such as a spreadsheet row, a message from an older system or a paper form, in the same way FHIR describes its own types: a StructureDefinition that lists the elements, what kind of value each holds and how many there may be. Once the shape is described, a map can read it or write it like any other.

5.1 A worked example🔗

A clinic’s front desk records blood-pressure readings on an intake form of its own design. The clinic’s record keeps them as Observations that must meet its screening profile. One project, fhir-examples/examples/intake-maps, holds the two shapes, the map between them and an example form.

1. The shapes, in FHIR Shorthand. The form is a logical model; the record is a profile of Observation; the last block is one filled-in form.

Logical: IntakeForm

Id: IntakeForm

* patientId 1..1 string "The patient's record id"

* measured 1..1 dateTime "When the reading was taken"

* systolic 1..1 integer "Systolic pressure, mm[Hg]"

* diastolic 1..1 integer "Diastolic pressure, mm[Hg]"

 

Profile: ScreeningBP

Parent: Observation

Id: ScreeningBP

* status = #final

* code = http://loinc.org#85354-9

* subject 1..1

* effective[x] 1..1

* effective[x] only dateTime

* component 2..*

 

Instance: intake-1

InstanceOf: IntakeForm

Usage: #example

* patientId = "p1"

* measured = "2024-03-01T09:00:00Z"

* systolic = 120

* diastolic = 80

2. The map. Its uses lines name the two shapes by their addresses. Each rule reads one element of the form and writes the part of the Observation it feeds.

/// url = 'http://example.org/intake/StructureMap/IntakeToBP'

/// name = 'IntakeToBP'

/// title = 'Intake form to screening blood pressure'

 

uses "http://example.org/intake/StructureDefinition/IntakeForm" alias Intake as source

uses "http://example.org/intake/StructureDefinition/ScreeningBP" alias BP as target

 

group IntakeToBP(source src : Intake, target tgt : BP) {

  src -> tgt.status = 'final', tgt.code = cc('http://loinc.org', '85354-9', 'Blood pressure panel') "panel";

  src.patientId as id -> tgt.subject as s, s.reference = append('Patient/', id) "subject";

  src.measured as m -> tgt.effective = m "when";

  src.systolic as v -> tgt.component as c, c.code = cc('http://loinc.org', '8480-6', 'Systolic blood pressure'),

                       c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "systolic";

  src.diastolic as v -> tgt.component as c, c.code = cc('http://loinc.org', '8462-4', 'Diastolic blood pressure'),

                        c.value = qty(v, 'mm[Hg]', 'http://unitsofmeasure.org', 'mm[Hg]') "diastolic";

}

3. Check everything at once. raco fsh check, the FHIR Shorthand tool’s check, also checks every map in the project against the shapes beside it, converts the example form and validates the result against the profile:

$ raco fsh check examples/intake-maps

fsh check: 1 example, 0 with errors; 0 errors, 0 warnings

  canonical: http://example.org/intake (…/examples/intake-maps/sushi-config.yaml)

Misspell an element, or leave out the rule for code, and it says so at the line.

5.2 From the command line🔗

raco fml needs to be told where your shapes are defined, since they are not part of FHIR. --structures names a file or a folder of StructureDefinitions as JSON. In the project above, raco fsh . writes them to fsh-generated/:

$ raco fsh .

  StructureDefinition-IntakeForm.json

  StructureDefinition-ScreeningBP.json

  IntakeForm-instance.json

  StructureMap-instance.json

fsh: wrote 4 artifact(s) to ./fsh-generated

$ raco fml IntakeToBP.map --transform form.json --structures fsh-generated

{"resourceType":"Observation","status":"final","code":{"coding":[{"system":"http://loinc.org","code":"85354-9","display":"Blood pressure panel"}]},"subject":{"reference":"Patient/p1"},"effectiveDateTime":"2024-03-01T09:00:00Z","component":[ … ]}

The data says which shape it is in the same place a FHIR resource does:

{"resourceType": "IntakeForm", "patientId": "p1", "measured": "2024-03-01T09:00:00Z",

"systolic": 120, "diastolic": 80}

raco fml check takes --structures too. Without it, a map over shapes the check cannot find gets no findings, because nothing can be decided about them.

5.3 As one package🔗

raco fsh examples/intake-maps --pack intake.tgz packs both shapes and the map into one FHIR package, the file format FHIR definitions are published in. (It also writes the compiled files to the project’s fsh-generated/ folder.) A program can then use the map by its address alone:

(require fml/registry fhir/sd/sd-index fhir/spec-package)
(parameterize ([current-sd-packages (list "intake.tgz" (spec-package-path "hl7.fhir.r5.core.tgz"))])
  (define to-bp (structure-map "http://example.org/intake/StructureMap/IntakeToBP"))
  (to-bp form))                                ; the Observation

Over HTTP, a server generated from that package serves the same map as StructureMap/$transform. The test that does all of this is fhir-examples/tests/intake-maps-test.rkt.

6 The StructureMap, and back to text🔗

A StructureMap is the FHIR resource a map compiles to: the same rules, as data rather than text. It is what a FHIR server stores and what tools pass to each other. You write and read the text; the StructureMap is made from it when needed.

  • raco fml map.map prints the StructureMap as JSON.

  • A StructureMap .json file can be given wherever a .map file can: to run it, or to check it.

  • raco fml --decompile StructureMap.json writes a StructureMap as text, so a map you received as a resource can be read and edited:

$ raco fml qr2pat.map > sm.json

$ raco fml --decompile sm.json

/// url = 'http://example.org/StructureMap/qr2patient'

/// name = 'QR2Patient'

/// status = 'draft'

 

uses "http://hl7.org/fhir/StructureDefinition/QuestionnaireResponse" as source

uses "http://hl7.org/fhir/StructureDefinition/Patient" as target

 

group main(source src : QuestionnaireResponse, target tgt : Patient) {

  src.item as item where (linkId = 'gender') -> tgt.gender = (item.answer.value.code) "gender";

  src.item as item where (linkId = 'birth') then {

    item.answer as a -> tgt.birthDate = (a.value) "birthDate";

  } "birth";

}

The text comes back in the language as the specification writes it today: the header lines, conditions in parentheses, rule names in double quotes, one rule to a line. Comments and layout are not part of a StructureMap, so they do not come back. Two things a StructureMap can hold have no agreed way to be written: a table of code translations inside the map, and a shared target named by a rule. A map with either is written in the older form for that part, under a comment that says so.

7 Running it🔗

7.1 Command line🔗

This table is every form of the command.

raco fml map.map

  

the StructureMap, as JSON

raco fml map.map --transform src.json

  

run the map over one piece of data; print the result

… --structures sds/

  

where the definitions of your own shapes are (a file or a folder)

… --indent

  

print the result over several lines

raco fml check map.map

  

the map against its shapes

… --structures sds/

  

as above

… --examples ex/

  

convert each example and validate the result

… --profile sd.json

  

hold the results to a profile: a JSON file, FHIR Shorthand, or an address; repeat it

raco fml --decompile sm.json

  

a StructureMap resource as text

raco fml --parse-corpus dir/

  

read every .map under a folder and write each back; for testing the tool on a collection

raco fml --tck

  

the test collections, with the scores they must not fall below

--format text|json|outcome chooses how problems are reported: as text for a person, or as JSON or a FHIR OperationOutcome for a program. The command ends with status 0 when all is well, 1 on an error in a map or a fall in a test score, and 2 when it was called wrongly or a file could not be read. A file is read the same with or without a #lang fml first line.

Giving a map data of the wrong type is refused before any rule runs:

$ raco fml qr2pat.map --transform obs.json

qr2pat.map:7:1: fml transform error: the source is of type Observation, but group main takes src : QuestionnaireResponse

7.2 As a module, from Racket🔗

Put #lang fml on the first line of a map and the file is a Racket module, so a program can require it and call it. The map is checked when the program is built: a misspelt element stops the build, at its line.

(require json "qr2pat.map")
(define (read-file f) (call-with-input-file f read-json))
(transform (read-file "qr.json"))
; '#hash((birthDate . "1980-02-03") (gender . "female") (resourceType . "Patient"))
(hash-ref structuremap 'url)        ; "http://example.org/StructureMap/qr2patient"

transform is the map as a function: FHIR JSON in, FHIR JSON out. The module also provides structuremap, the StructureMap, and fml, the map as parsed. Running the file itself (racket qr2pat.map) prints the StructureMap.

transform takes three options:

  • #:validate checks the result and raises an error that names the rule, as raco fml check --examples does. Give it #t for FHIR’s own rules, or a profile: its address, a folder of FHIR Shorthand, a StructureDefinition, or a list of these. With the profile and the text-answer form of Checking a map, (transform (read-file "bo.json") #:validate "fsh/") raises:

    the map's Patient is invalid against IntakePatient (http://example.org/StructureDefinition/intake-patient) (FHIR R5 (5.0.0)):

      qr2pat.map:9:49: fml validate error: Patient.gender: minimum required = 1, but found 0 (the rule here wrote nothing: its source matched, but `(item.answer.value.code)` was empty for {"answer":[{"valueString":"male"}],"linkId":"gender"})

    The error is an exn:fail:operation, the same kind ensure-valid raises, so one handler catches both.

  • #:structures gives the definitions of your own shapes (Shapes of your own: logical models), as a list of StructureDefinitions or a data source.

  • #:strict? makes a source value that cannot be read an error. Without it, such a value is a warning and the map runs without it.

A map module fits into a pipeline with the family’s other tools. Here the result is validated against a profile by its address, with ~> passing each step’s result to the next:

(require (only-in "qr2pat.map" [transform form->patient])
         fhir/operation (only-in fhir/conformance/operations ensure-valid))
(~> qr form->patient (ensure-valid #:profile "http://hl7.org/fhir/StructureDefinition/Patient"))

Requiring the module also registers the map under its url, which the next section uses.

7.3 By its address, or as a FHIR operation🔗

A program does not need the file to use a map: it can ask for it by its url. structure-map finds the map among those registered in the program, then in the current data source, then in the installed packages, and gives it back as a function that knows its source and target types.

(require fml/registry fml/operations fhir/operation
         (only-in fhir/conformance/operations ensure-valid))
(define to-patient (structure-map "http://example.org/StructureMap/qr2patient"))
(list (smap-source to-patient) (smap-target to-patient))   ; '(QuestionnaireResponse Patient)
(to-patient qr)                                            ; FHIR JSON in, FHIR JSON out
(ensure-valid (to-patient qr))                             ; convert, then validate
((compose-maps a b) x)                                     ; b after a; refused unless a's target is b's source
(apply-operation "StructureMap/$transform" qr #:srcMap fml-text)
(apply-operation "StructureMap/$transform" qr #:source "http://example.org/StructureMap/qr2patient")

StructureMap/$transform is the operation FHIR defines for running a map, and what a FHIR server offers over HTTP. It takes the map as text (srcMap), by address (source) or as a StructureMap resource (sourceMap).

7.4 The pieces, from Racket🔗

These are the steps the command line and the module form do for you, one at a time: read the text, compile it, check it, run it, write it back.

(require fml/parser/parse fml/structuremap fml/print fml/transform fml/check fhir/result/result
         fhir/r5/schemas fhir/serialize/from-json)             ; the engine needs FHIR's types loaded
(define m (ok-value (parse-fml text #:source "qr2pat.map")))
(fml->structuremap m)                                           ; the StructureMap
(check-map m)                                                   ; the findings; '() when there are none
(run-map m (ok-value (from-json qr #:lenient? #t)))            ; typed source in, target JSON out
(structuremap->fml sm)                                          ; a StructureMap back to the parsed map
(fml->text m)                                                   ; the parsed map as text
(specification-notes m)                                         ; the older forms the text used, as warnings

8 How a map runs🔗

This section says what happens, in order, when a map is run. You need it when a result surprises you.

A run starts at the first group, with the data you gave as its source and an empty target.

  • A rule runs once for every match of its source. The matches are the values of the element, narrowed by the list mode (first, last, not_first, not_last, only_one) and by where. A rule with several sources runs for every combination. A rule whose source matches nothing does nothing.

  • Then the checks. The stated number of values (1..1) and the check condition must hold, or the run stops with an error naming the rule. log sends its value to current-fml-log.

  • Then the targets, in order, then the group calls after then, then the rules inside.

  • A target with no value (tgt.component as c) makes the element.

  • A rule with one source, one target and no value (src.a -> tgt.a;) carries the value over. A simple value is copied and converted to the kind the target element holds: "12345" into an integer element is 12345. A structured value is handed to the group marked <<types>> or <<type+>> whose inputs are of those types, or copied whole when there is none.

  • A group that extends another runs that group’s rules first.

  • translate looks a code up in a table of code translations: a conceptmap block in the map, or a ConceptMap resource the terminology service can find.

  • A write takes one value. When the FHIRPath on the right finds several, the first is written.

An error while running names the rule and shows its line. For an unknown transform it lists the ones there are. A call to a group that does not exist is the exception: it names the groups there are, but comes without a line. The check catches it beforehand.

9 In an editor, and for an AI agent🔗

  • In an editor. The family’s language server, fhir-lsp, underlines a map’s mistakes as you type (the same findings as the check), lists its groups, shows what a name stands for, jumps from a name to where it is declared (from an imports address to the map that has it) and completes names and keywords. It treats the maps in the same folder as one project.

  • For an agent. In an fhir-mcp workspace a map is checked as it is written. run converts every piece of data of the map’s source type and validates each result; explain converts one and traces each problem to the rule that wrote the element. The repository’s guide.md is the language written for an agent to read (fhir-mcp serves it as learn://fml), and .claude/skills/fml is the same workflow for an agent using the command line.

For someone building on these: the editor support is the module fml/support (a fhir/lang/support value, which the language server loads by name), and the workspace support is fml/workspace.

10 Limits🔗

  • Three transforms are missing. escape, dateOp and pointer are not implemented. The check does not flag them; the rule fails when it runs, with the list of the ones there are.

  • One version of FHIR. Maps run over FHIR R5. Data from another version is read as far as it fits, and the run names each value it could not read. An element R5 dropped (R4’s Composition.code) is not an element here.

  • JSON only. Data is read and written as JSON. Maps that produce XML documents, such as CDA, are not supported.

  • Imports that cannot be found are skipped. An imports address no registered map, data source or package answers is ignored without a message. The check then cannot tell whether a group the map calls exists, and says nothing; the call fails when the map runs.

  • Only share among the target list modes has an effect. Of the words that can follow a target (first, last, share, single), only share changes what a run does. The others are kept in the StructureMap and otherwise ignored.

  • as in FHIRPath must be written as the function .as(Type) inside a map.

  • What cannot be decided is not reported. The check says nothing about a type whose definition it cannot find, so a clean check of a map over your own shapes means something only when their definitions were given.

11 Words used here🔗

  • Map: a text file of rules that convert data of one shape into another.

  • Source, target: the data a map reads, and the data it produces.

  • Rule: one line of a map: what to take from the source, and where to write it in the target.

  • Group: a named list of rules with its sources and targets. A run starts at the first.

  • Transform: a built-in helper that makes a value, such as cc or qty.

  • Resource: one record in FHIR, of a named type: a Patient, an Observation. Element: one named part of it, such as a Patient’s birthDate.

  • QuestionnaireResponse: the FHIR resource that holds the answers to a form.

  • StructureMap: the FHIR resource a map compiles to; the form in which tools store and exchange maps.

  • StructureDefinition: the FHIR resource that describes a shape: its elements, their kinds and how many of each there may be.

  • Logical model: a StructureDefinition for a shape of your own that is not a FHIR resource.

  • Profile: a StructureDefinition that narrows a FHIR type for one setting: this element is required here, that one must have this code.

  • Validate: to check a piece of data against the definition of its type and any profiles.

  • Canonical (url): the address a definition or a map is known by. It identifies; it need not be a working web address.

  • FHIRPath: FHIR’s language for picking values out of data: item.answer.value.

  • Choice element: an element written under different names for different kinds of value, such as valueString or valueQuantity. In a map, and in FHIR’s own definitions, it is just value.

  • Coding, CodeableConcept, Quantity: FHIR’s values for a code from a code system, a coded concept, and a number with a unit.

  • ConceptMap: a table that translates the codes of one code system into another’s.

  • Package: a file of published FHIR definitions (.tgz).

  • FHIR Shorthand (FSH): the language profiles and logical models are usually written in. It is the fsh package of this family.

  • R4, R5: versions of FHIR. R5 is the newer.

12 How it is tested🔗

Against maps other people published, not only its own examples:

  • HL7’s mapping test cases: all 6 that can be run here give the expected result, and all 15 maps are read. Four more are skipped: they produce XML, or take their map as JSON.

  • The maps of matchbox, another engine for this language: all 43 are read, and the 17 that can be run on their own are.

  • HL7’s mapping tutorial, thirteen steps over shapes of its own: all 37 results are as expected, both from the text and from the StructureMaps this package makes from it. Two result files in that collection are set aside, because the other engine’s own tests do not expect them: one belongs to a map it never runs, and one to a run it expects to fail, as it does here.

  • Every one of those 58 maps survives the trip to a StructureMap and back, and comes out of --decompile as text that means the same map. So do the 25 StructureMap resources matchbox ships.

  • The check finds nothing wrong in 55 of the 58. The other three have real mistakes: two use elements FHIR R5 dropped, one misspells a name.

  • The 332 maps HL7 wrote to convert between FHIR R3 and R4 are all read and written back.

The repository’s TESTING.md has the full table and names every difference. To run the tests yourself, install the family from source as the front page describes; then, in this repository, raco test . runs the unit tests and raco fml --tck runs the collections above.
